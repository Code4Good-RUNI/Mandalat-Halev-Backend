# Mandalat-Halev-Backend

ברוכים הבאים לשרת Mandalat-Halev-Backend!  
מסמך זה מסביר מה יש בקוד, מה מטרת השרת, ואיך ניתן לעבוד איתו.

---

## מה השרת עושה?

השרת מספק API מבוסס Express.js עבור אפליקציית Mandalat-Halev.  
הוא כולל אינטגרציה עם Salesforce, אימות משתמשים (באמצעות קוד אימות בSMS), וממשקי ניהול משתמשים.

### יכולות עיקריות:
- **אימות משתמשים**: שליחת קוד אימות לנייד, אימות קוד, והנפקת JWT.
- **אינטגרציה עם Salesforce**: בדיקת משתמשים מול מסד ה־Contact של Salesforce.
- **ניהול משתמשים**: שליפת פרופיל משתמש (דורש התחברות).
- **API JSON בלבד**: אין תצוגות, הכל מבוסס JSON.

---

## מבנה הפרויקט

- `app.js` – קובץ הכניסה הראשי, מגדיר את ה־Express, ראוטים ומידלוורים.
- `routes/` – תיקיית הראוטים (auth, users, salesforce וכו').
- `middleware/` – מידלוורים לאימות, טיפול בשגיאות ועוד.
- `.env` – משתני סביבה (לא כלול בגיט).

---

## תקשורת עם Salesforce

השרת מבצע אינטגרציה עם Salesforce באמצעות OAuth2.  
בעת אתחול השרת, מתבצעת התחברות ל־Salesforce עם פרטי הלקוח (`client_id` ו־`client_secret`) שמוגדרים בקובץ ה־`.env`.  
השרת שומר את ה־access token בזיכרון, ומרענן אותו אוטומטית כאשר הוא פג תוקף.

בכל קריאה שדורשת מידע מ־Salesforce (למשל, בדיקת קיום משתמש לפי אימייל), השרת שולח בקשת API ל־Salesforce עם ה־token.  
אם ה־token אינו תקף, השרת מנסה להתחבר מחדש ולקבל token חדש.

**הערה:** אין שמירה של מידע רגיש מה־Salesforce במסד נתונים מקומי – כל הבדיקות נעשות בזמן אמת.

---

## תהליך התחברות משתמש קצה

1. **בקשת קוד אימות:**  
   המשתמש שולח בקשה עם מזהה משתמש (`userId`) ואימייל ל־`/auth/request-code`.  
   השרת בודק מול Salesforce אם המשתמש קיים במערכת.  
   אם כן, נשלח קוד אימות חד־פעמי (OTP) לכתובת המייל של המשתמש.

2. **אימות קוד:**  
   המשתמש מזין את הקוד שקיבל במייל ושולח אותו ל־`/auth/verify-code` יחד עם מזהה המשתמש והאימייל.  
   השרת בודק אם הקוד תואם ונמצא בתוקף.  
   אם כן, השרת מנפיק למשתמש טוקן JWT.

3. **שימוש בטוקן:**  
   המשתמש מצרף את ה־JWT לכל בקשה מוגנת (למשל, `/auth/protected-contacts`) באמצעות כותרת `Authorization`.  
   השרת בודק את הטוקן ומאפשר גישה רק למשתמשים מאומתים.

**הערות אבטחה:**  
- קודי האימות נשמרים בזיכרון (או ב־Redis/DB בפרודקשן) עם תוקף קצר.
- ה־JWT חתום עם סוד (JWT_SECRET) ואינו נשמר בשרת – אימות מתבצע על כל בקשה.

## התקנה והרצה

### דרישות מוקדמות

הפרויקט נבנה ב־Node.js.  
לפני שמתחילים, יש להתקין את סביבת Node.js (כולל npm) על המחשב.  
להורדה והתקנה: [https://nodejs.org/](https://nodejs.org/)

---

### ספריות עיקריות בפרויקט

- **express** – מספקת את תשתית ה־HTTP וה־API, ניהול ראוטים ומידלוורים.
- **forcejs** – ספרייה לאינטגרציה עם Salesforce API, כולל ניהול OAuth2 ושליחת בקשות.
- **jsonwebtoken** – משמשת להנפקה ואימות של JWT עבור אימות משתמשים.
- **dotenv** – מאפשרת טעינת משתני סביבה מקובץ `.env`.
- **body-parser** – עוזרת בפירוק נתוני JSON שמגיעים בבקשות לשרת.
- **cors** – מאפשרת קבלת בקשות ממקורות שונים (CORS) – שימושי במיוחד בפיתוח מול פרונטאנד נפרד.
- **nodemon** (dev dependency) – להרצה אוטומטית של השרת מחדש בעת שינוי קבצים (לסביבת פיתוח).

---

### קובץ הגדרות סביבה (`.env`)

כדי שהשרת יוכל להתחבר ל־Salesforce ולהנפיק JWT, יש ליצור קובץ `.env` בתיקיית הפרויקט עם הערכים הדרושים:

```env
# Salesforce
host=https://mandalathalev.my.salesforce.com
client_id=YOUR_SALESFORCE_CLIENT_ID
client_secret=YOUR_SALESFORCE_CLIENT_SECRET

# JWT
JWT_SECRET=your_jwt_secret
```

> **הערה:**  
> את ה־`client_id` וה־`client_secret` יש לקבל מתיקיית הדרייב של code4good.  
> ערכים אלו סודיים ואין להעלות אותם לגיטהאב או לשתף אותם באופן שאינו מבוקר.

> **טיפ אבטחה:**  
> בחרו ערך חזק וייחודי עבור `JWT_SECRET` – זהו המפתח לחתימה ואימות של הטוקנים במערכת.

---

לאחר יצירת קובץ ה־`.env`, התקינו את התלויות באמצעות:

```bash
npm install
```

והריצו את השרת:

```bash
npm start
```

לסביבת פיתוח (עם טעינה אוטומטית):

```bash
npm run dev
```
